# 기존 코드 안정화 결과와 Kali 검증 절차

실제로 검증을 진행할 때는 [기존 기능 검증 실행 안내](existing-features-checklist.md)를 따른다.
항목별 명령, 정상 결과, 실패 확인 위치, 시험 설정 복구와 결과 기록표를 제공한다.

## 1. 완료 범위와 남은 검증

이번 변경은 기존 코드 안정화다. DNS·Grafana·새 AI 모델은 구현하지 않았다.

| 항목 | 확인 결과 |
| --- | --- |
| `plot.run()` 오류 | 필수 artifact 경로 누락을 재현하고 `LoadedArtifacts` 객체 접근으로 수정 |
| 그래프 회귀 테스트 | 실제 모델 파일·CSV로 PNG 세 개와 기존 완료 메시지를 확인 |
| 기존 정상 행 분할 | seed·비율·행 선택 결과를 유지하고 원본 유효 행 인덱스 조회를 분리 |
| 데이터 점검 도구 | 입력 SHA-256·분할 지문·동일 특징 중복을 보고하고 기존 보고서 덮어쓰기 거부 |
| Python 전체 테스트 | Windows에서 41개 중 39개 통과, Linux root 전용 2개 skip |
| Ruff / Bandit | 오류 없음 / 탐지 항목 없음 |
| CI | 인식 경로·의존성·테스트 명령 수정, YAML 구문 확인. GitHub 실제 실행은 미확인 |
| C++ 빌드·CTest·Clang-Tidy | Windows에 Linux 도구체인이 없어 미실행 |
| root 소유권·symbolic link 검사 | Kali에서 실행 필요 |
| NFQUEUE·Qt·공격 시나리오·처리량 | Kali와 격리된 실험 네트워크에서 실행 필요 |
| 실제 CICIDS2017 분할·누수 | CSV 경로가 제공되지 않아 미검증. 합성 CSV 테스트와 구분 |

위 결과는 전체 출시 승인이나 Linux 동작 보장이 아니다. 기준선 안정화의 Linux·실데이터 검증은
아직 남아 있다. 기존 IP TTL 차단과 schema 1의 27개 특징 계약은 변경하지 않았다.

## 2. 재현 환경과 명령

Windows 가상환경: Python 3.12.14, PyTorch 2.14.0+cpu, NumPy 2.3.5, pandas 3.0.1,
scikit-learn 1.9.1, Matplotlib 3.11.2, Ruff 0.16.7, Bandit 1.9.4.
이 목록은 측정 당시 버전이며 의존성 잠금 파일을 대신하지 않는다.

```powershell
$env:MPLCONFIGDIR = Join-Path (Get-Location) '.venv\matplotlib-cache'
.\.venv\Scripts\python.exe -X utf8 -W ignore::UserWarning -m unittest discover -s tests -p 'test_*.py'
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m bandit -r ml -ll
git diff --check
```

`MPLCONFIGDIR`은 실행 환경의 기본 캐시 경로 쓰기 제한을 피한다. 그래프 테스트의 한글 글꼴
경고는 `-W ignore::UserWarning`으로 숨겼으며, 예외·assertion 실패나 테스트 skip을 숨긴 것은
아니다. root 전용 두 테스트는 Windows에서는 의도적으로 실행하지 않는다.

수정 전에는 32개 테스트 중 그래프 loader 계약 1개가 실패하고 root 전용 2개가 skip됐다.
수정 뒤에는 분할 인덱스 2개·데이터 점검 7개 테스트가 추가됐다. 그래프 테스트는 mock 호출 확인에서
실제 PNG 산출물 확인으로 교체했다. 전처리·학습·추론을 일괄 재포맷하지 않았다.

## 3. Kali에서 자동 테스트하기

### 준비

Windows의 `.venv`와 `build`를 재사용하지 않는다. 저장소 소스만 Kali의 Linux 파일시스템에
옮긴다. root 권한 테스트까지 실행할 복사본은 `/opt/ips-with-ai-src`처럼 상위 경로까지 root가
관리하는 위치에 두고, 저장소·테스트 디렉터리를 group/other가 수정할 수 없게 준비한다.
Windows 공유 디스크의 소유권 표시만으로 root 보안 검사를 통과했다고 판단하지 않는다.

아래는 **Kali에서 실행할 명령**이며 이 작업 중 실제 실행한 결과가 아니다.
기존 `/opt/ips-with-ai-src`가 있다면 덮어쓰지 말고 먼저 내용을 확인한다.

```bash
sudo apt update
sudo apt install -y build-essential cmake pkg-config iptables \
  libnetfilter-queue-dev libgoogle-glog-dev nlohmann-json3-dev \
  libzmq3-dev cppzmq-dev qtbase5-dev libgtest-dev python3-venv
```

저장소 복사가 끝난 뒤 root 터미널에서:

```bash
cd /opt/ips-with-ai-src
python3 -m venv .venv
.venv/bin/python -m pip install 'torch>=2.1' --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install -r ml/requirements.txt
cmake -S . -B build -DPython3_EXECUTABLE="$PWD/.venv/bin/python"
cmake --build build -j2
ctest --test-dir build --output-on-failure
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

명령이 실패하면 그 지점에서 원인을 확인한다. 마지막 명령 성공만으로 앞선 빌드 실패를 무시하지
않는다. 이 단계는 센서를 실행하거나 iptables 규칙을 등록하지 않는다. CTest의 온라인 AI 테스트는
이 가상환경 interpreter로 실행한다. 센서 본체가 자동 실행하는 `/usr/bin/python3`의 runtime 경로는
[README](../../README.md)의 별도 설치 절차를 따른다.

Kali 시스템 Python을 `sudo pip install`이나 `--break-system-packages`로 변경할 필요는 없다.
[Kali Python 패키지 안내](https://www.kali.org/docs/general-use/python3-external-packages/)에 따라
프로젝트 가상환경을 사용한다. venv 자체는 운영체제 사이에 복사해 재사용하지 않는다.
[Python venv 문서](https://docs.python.org/3/library/venv.html)

### 결과에서 확인할 것

- CTest의 C++ 테스트와 온라인 Python 테스트가 모두 통과하는지 확인한다.
- root 실행의 `test_artifacts.py`에서 group/other 쓰기 권한·symbolic link 테스트가 skip되지 않아야 한다.
- 출력에 표시되는 테스트 수·실패·skip 사유, Python·컴파일러·커널 버전을 함께 보관한다.

## 4. 실제 데이터 분할 점검

실제 CSV를 준비한 저장소 루트에서 실행한다. `data` 폴더와 입력 CSV는 먼저 존재해야 한다.
출력 파일 이름은 기존 보고서와 겹치지 않게 정한다.

```bash
.venv/bin/python -m ml.audit_dataset \
  --data 'data/*.csv' --output data/split-audit-first.json
```

이 도구는 모델을 학습하거나 기존 분할을 변경하지 않는다. 보고서의 의미는 다음과 같다.

| 필드 | 확인할 내용 |
| --- | --- |
| `sources` | 실제 읽은 파일 순서·절대 경로·내용 SHA-256 |
| `rows` | 전체·유효·제외 행과 정상·공격 수 |
| `split` | 현재 `row_random`, seed 42, 60/20/20 비율 |
| `splits` | 정상 train/validation/test 크기와 유효 행 인덱스 SHA-256 |
| `feature_overlap` | 분할 사이에 공유되는 동일 27개 특징 지문의 종류 수. 행 개수와 다름 |
| `group_isolation` | 항상 `not_checked`. 날짜·세션 격리는 확인하지 않았다는 뜻 |

서로 다른 세션도 같은 27개 특징을 가질 수 있으므로 중복은 잠재적 누수 신호다. 반대로 중복이
없어도 시간·세션 누수가 없다는 증거가 아니다. 실제 날짜·세션 식별 정보와 그룹 분할 정책을
확정하고 train/validation/test 격리를 확인하기 전에는 최종 모델 성능으로 보고하지 않는다.
점검 파일은 해당 데이터의 기록이며, 이미 학습된 모델이 바로 그 데이터로 학습됐다는 증명도 아니다.

## 5. 센서·AI 통합 검증과 성능 기준선

자동 테스트 이후, root GUI 로그인과 실제 모델 artifact·runtime 설치를 준비한다. 듀얼 부팅한
Kali 한 대만으로 외부 공격자까지 분리되는 것은 아니다. 공격자 VM/별도 장비 또는 별도 검증된
격리 네트워크를 마련하고 일반 사용 중인 네트워크에는 공격 트래픽을 보내지 않는다.

| 시나리오 | 남길 증거 |
| --- | --- |
| 정상 시작·종료 | INPUT/OUTPUT 관리 규칙 등록·제거, Qt 상태 |
| Rule 탐지 | 포트 스캔·SYN Flood 적중과 실제 DROP, 정상 대조 트래픽 결과 |
| AI 탐지 | 판정·원본 Flow·IP TTL 등록과 적용 이후 수신 차단, 기존 연결 영향 |
| whitelist·TTL | 차단 면제, 중복 결과로 TTL 미연장, 만료 후 허용 |
| AI 중지·timeout | 최대 3회 재시작과 Rule-only 지속, 패킷 경로가 응답을 기다리지 않음 |
| 큐 포화·센서 정지 | AI 큐와 커널 NFQUEUE 손실·지연을 따로 기록 |
| 부하 측정 | 입력률, 처리량, p50/p95 지연, 메모리, 커널 drop, IPS·모델·커널 버전 |

학습 CSV 특징과 실제 C++ 특징의 순서·단위·방향·타임아웃 차이도 검증 대상이다. 합성 특징 테스트만으로
CICFlowMeter와 실트래픽 추출이 완전히 같다고 주장하지 않는다.

## 6. CI 확인

워크플로는 `.github/workflows/my_ci_cd.yml`에 있다. Python 전체 테스트와 기존 Ruff/Bandit,
C++ 의존성·빌드·Clang-Tidy·CTest, root 소유 임시 복사본의 artifact 권한 테스트를 구성했다.
GitHub에서 이 변경이 포함된 push/PR 또는 수동 실행의 결과를 확인해야 CI 성공으로 기록할 수 있다.
이번 작업은 push나 원격 워크플로 실행을 하지 않았다.

참고: [GitHub Python CI 안내](https://docs.github.com/en/actions/tutorials/build-and-test-code/python).

## 7. 안정화 이후 합의한 작업

Kali·실데이터 검증을 마친 뒤 [DevOps·IaC 학습 로드맵](../design/devops_iac_learning_roadmap.md)에
따라 로컬 읽기 전용 Grafana 통계 대시보드를 추가한다.
통계 전달 → Prometheus → Grafana로 연결하고 Qt 즉시 알림은 유지한다. 차단·설정 변경 화면은
첫 범위에서 제외하며, 관제 구성의 장애가 패킷 처리 경로를 중단시키지 않게 분리한다.
구체적인 지표·수집 경로·보관 기간·설치 방식은 로드맵의 다음 설계에서 정한다. Grafana와
IaC는 아직 설치·구현하지 않았다.
