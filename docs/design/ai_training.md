# AI 엔진 설계 — 오프라인 학습 (오토인코더 이상 탐지)

> AI 기반 인라인 IPS · Python 분석 엔진
> 대상 범위: #1 AI 엔진 중 **오프라인 학습** — CICIDS2017로 오토인코더를 학습시켜 모델을 만드는 부분
> 선행 문서: `overview.md`(개념 설계), `flow_features.md`(C++ 특징 토대)
>
> **이 문서는 AI 초보자도 읽을 수 있게 "왜 이렇게 하는지"를 붙여 썼다.** 발표 방어용 밑천으로도 쓴다.

---

## 1. 이 문서의 범위

AI 엔진은 두 덩어리다. 이 문서는 **오프라인 학습**만 다룬다.

- **오프라인 학습 (이 문서)** — 데이터로 모델을 만든다. 파이썬이라 Windows에서 바로 돌아간다. 딱 한 번(또는 가끔) 돌리는 작업.
- **온라인 추론 (다음 문서)** — 만든 모델을 실제 센서에 붙여 실시간 판정. C++와 ZeroMQ로 통신. Linux VM에서 동작.

이 학습이 끝나면 **산출물 4개**(모델·정규화 기준·임계값·특징 목록, 10장)가 나온다. 이게 추론 단계와 C++가 지킬 **계약**이다.

---

## 2. 핵심 아이디어 (비유로)

**정상 트래픽만 수천 번 "따라 그리기" 시킨 사람**을 상상하자. 정상만 봤으니 정상은 눈 감고도 똑같이 그린다. 그런데 **공격 트래픽**을 주면? 처음 보는 모양이라 **엉망으로 그린다.**

그 "얼마나 엉망으로 그렸나"가 경보다.
- 잘 그림 → 정상과 비슷 → 통과
- 못 그림 → 정상과 다름 → 공격 의심

이 "압축했다 다시 복원하는 모델"이 **오토인코더(autoencoder)** 다. 정상만 학습해서, 정상은 잘 복원하고 낯선 것은 복원을 못 한다. "얼마나 못 복원했나"를 숫자로 잰 게 **복원 오차(reconstruction error)** 다.

---

## 3. 왜 오토인코더인가 (왜 그냥 분류기가 아니고)

"공격이면 1, 정상이면 0" 맞히는 **분류기**를 만들 수도 있다. 하지만:

- 분류기는 **공격을 라벨로 가르쳐야** 한다 → 가르친 공격만 잡는다.
- 새로운(처음 보는) 공격, 즉 **제로데이는 못 잡는다.**

오토인코더는 **정상만 배운다.** "정상과 다르다"만 보므로 **가르친 적 없는 신종 공격도 잡을 수 있다.** 이게 룰 기반 장비가 못 하는 차별점이고, 이 프로젝트의 핵심 셀링포인트다 (overview.md 4.2).

## 4. 특징 (~27개) — 우리 C++ 토대에서 나오는 것만

AI가 보는 것은 플로우 하나를 요약한 **숫자 목록(특징 벡터)** 이다. CICIDS2017엔 특징이 ~80개 있지만, **우리 C++ 센서가 실제로 뽑을 수 있는 것만** 골라 쓴다 (안 그러면 학습은 되는데 실제 서비스에서 그 값을 못 만든다).

우리 `flow_features.md`의 `DirectionStats`(방향별 통계)에 대응되는 것들:

| 우리 토대 | CICIDS2017 특징 |
| --- | --- |
| 지속시간 | Flow Duration |
| 방향별 패킷 수 | Total Fwd Packets, Total Backward Packets |
| 방향별 바이트 수 | Total Length of Fwd/Bwd Packets |
| fwd 패킷 크기 통계 | Fwd Packet Length Max/Min/Mean/Std |
| bwd 패킷 크기 통계 | Bwd Packet Length Max/Min/Mean/Std |
| fwd 패킷 간격 통계 | Fwd IAT Mean/Std/Max/Min |
| bwd 패킷 간격 통계 | Bwd IAT Mean/Std/Max/Min |
| 플래그 카운트 | FIN/SYN/RST/PSH/ACK/URG Flag Count |

- CICFlowMeter의 "Flow IAT"(양방향 섞은 간격) 대신 "Fwd/Bwd IAT"(방향별)를 골랐다 — 우리 토대가 방향별로만 재기 때문이다.
- 플래그 카운트는 CICIDS2017에선 플로우 전체 합이다. 우리 토대는 방향별이므로 fwd+bwd를 더해 맞춘다.
- **정확한 컬럼 이름은 CSV 헤더를 받아 확인한 뒤 확정한다** (CICIDS2017 버전마다 철자·공백이 조금씩 다르다). 위 표는 의도한 특징 집합이다.

## 5. 데이터셋 — CICIDS2017

- 캐나다 뉴브런즈윅대(UNB) 사이버보안연구소(CIC)가 만든 침입 탐지 평가용 데이터셋.
- **CSV 형태**(라벨된 플로우 특징)를 받는다. `MachineLearningCSV` 묶음. 원본 PCAP은 받지 않는다.
- 요일별 CSV 8개 정도. 월요일=전부 정상, 화~금=공격 섞임(PortScan, DoS, DDoS, 웹 공격 등). 각 행이 플로우 하나, 마지막 열이 `Label`.

**알려진 함정 (전처리에서 처리):**
- 컬럼 이름 앞에 공백이 붙어 있다 → 공백 제거.
- 일부 열에 `Inf`/`NaN`(빈 값)이 있다 → 우리가 고른 특징에 그런 값이 든 행은 **버린다** (정상 데이터가 많아 드롭으로 충분).
- 데이터 대부분이 정상(BENIGN)이다 → **우리는 정상만 학습하므로 오히려 유리하다.**

## 6. 파이프라인 (단계마다 "왜")

```
CSV 로드 (요일별 8개 합치기)
  → 정리        : 컬럼명 공백 제거, NaN/Inf 행 처리, 위 ~27개 특징만 선택
  → 분리        : 정상만 뽑아 train/val/test로 나눔 (예: 60/20/20)  ← 커닝 방지
  → 정규화      : z-score, 정상 train에만 기준을 맞춤  ← 정보 누수 방지
  → 학습        : 오토인코더를 정상 train으로 학습  ← 정상을 "잘 복원"하게
  → 임계값 결정 : 정상 val의 복원오차 분포에서 컷 정하기
  → 평가        : 정상 test(오탐률) + 공격 샘플(탐지율)
  → 저장        : 산출물 4개 (10장)
```

- **왜 정상만 학습하나**: 오토인코더의 원리(2·3장). 정상만 잘 복원하게 만들어야 공격이 튄다.
- **왜 train/val/test로 나누나**: 같은 데이터로 학습하고 채점하면 커닝이다. 연습용(train)·조정용(val)·최종시험용(test)을 나눠, 성능을 정직하게 잰다.
- **왜 정규화하나**: 특징들의 숫자 크기가 제각각이다(지속시간은 백만 단위, 플래그 수는 한 자리). 안 맞추면 큰 숫자 특징만 모델을 지배한다. z-score는 각 특징을 "평균 0, 퍼짐 1"로 맞춘다. 기준(평균·퍼짐)은 **정상 train에서만** 계산한다 — val/test 값을 미리 엿보면 커닝이라서.

---

## 7. 모델 구조

작은 **MLP 오토인코더**다.

```
입력(~27) → 16 → 8(병목) → 16 → 출력(~27)
```

- 가운데 **병목(8)** 이 핵심이다. 27개를 8개로 줄였다 다시 27개로 늘린다. 좁은 병목을 억지로 통과시키면 "정상의 핵심 패턴"만 남고 잡음은 버려진다. 그래서 정상은 잘 복원되고, 낯선 공격은 병목을 못 빠져나와 복원이 깨진다.
- 손실 함수(모델이 줄이려 애쓰는 값) = **복원 오차(MSE)**. 입력과 출력의 차이를 제곱해 평균낸 것.
- **작아서 GPU 없이 CPU로 충분하다.** 이 Windows 머신에서 돌아간다.

---

## 8. 임계값 — "이 선 넘으면 공격"

학습이 끝나면 정상 val 데이터를 넣어 **복원 오차 분포**를 본다. 정상들의 오차는 대부분 작다. 그 분포의 **99퍼센타일**(정상의 99%가 이 아래인 지점)을 임계값으로 잡는다.

- 임계값을 **낮추면** → 더 예민하게 잡음(탐지율↑) but 헛경보↑(오탐↑).
- 임계값을 **높이면** → 헛경보↓ but 놓치는 공격↑.
- 이 프로젝트는 오탐(정상 서비스 마비)이 1차 리스크라(overview.md 6장) 오탐을 통제하는 쪽으로 잡되, 학습해보고 조정한다.

---

## 9. 평가 — 잘 됐는지 어떻게 아나

- **오탐률(false positive)**: 정상 test를 넣어 임계값을 잘못 넘는 비율. 낮아야 좋다.
- **탐지율(recall)**: 공격 샘플을 넣어 임계값을 제대로 넘는 비율. 높아야 좋다.
- 공격 종류별(PortScan/DoS/…)로도 본다 — 어떤 공격을 잘/못 잡는지.
- **성공 기준**: "오탐 낮게 유지하면서 유의미한 탐지율". 구체 목표 수치는 첫 학습 결과를 보고 잡는다.

## 10. 산출물 (계약)

학습이 남기는 파일들. 추론 단계(B)와 C++가 이걸 지켜야 한다.

| 산출물 | 내용 | 왜 필요 |
| --- | --- | --- |
| 모델 가중치 | 학습된 오토인코더 | 추론이 로드해 씀 |
| 정규화 기준 | 특징별 평균·퍼짐(스케일러) | 추론도 **같은 기준**으로 정규화해야 함 |
| 임계값 | 복원오차 컷 값 | 이 선을 넘으면 이상 |
| 특징 목록·순서 | 어떤 특징을 어떤 순서로 | C++가 **같은 순서**로 벡터를 만들어야 함 |

순서가 어긋나면 전부 틀어지므로, 특징 목록·순서를 명시적으로 저장한다.

## 11. 기술·파일 배치

Python, PyTorch(오토인코더), pandas·numpy(전처리). C++와 완전 분리된 `ml/` 폴더.

```
ml/
├── preprocess.py     # CSV 로드·정리·특징 선택·정규화
├── model.py          # 오토인코더 정의
├── train.py          # 학습 + 임계값 결정 + 산출물 저장
├── evaluate.py       # 오탐률·탐지율 측정
├── requirements.txt  # torch, pandas, numpy, scikit-learn
└── artifacts/        # 산출물 4개 저장 위치 (모델·스케일러·임계값·특징목록)
```

## 12. 이 단계에서 미루는 것

- **온라인 추론(B)** — 모델 로드 → ZeroMQ 수신 → 실시간 판정. 다음 문서.
- **C++ 특징 추출 정합** — C++가 계약대로 특징을 뽑는 것, train/serve 값 차이(skew) 관리. 추론·연동 단계에서.
- **하이퍼파라미터 심화 튜닝** — 층 크기·학습률 등 최적화. 일단 표준값으로 돌려보고 필요하면.
- **지도학습 결합**(랜덤포레스트 등 이중 탐지) — overview.md 9장대로 여유 되면.

## 13. 미니 용어집 (초보자용)

- **특징(feature)**: 플로우를 요약한 숫자 하나 (예: 평균 패킷 크기).
- **특징 벡터**: 그 숫자들을 정해진 순서로 모은 목록.
- **오토인코더**: 압축했다 복원하는 모델. 정상만 배워 이상 탐지에 씀.
- **복원 오차**: 입력을 얼마나 못 되살렸나. 크면 이상 의심.
- **정규화**: 특징들 숫자 단위를 같은 잣대로 맞추기 (z-score).
- **임계값**: 이상/정상을 가르는 복원오차 경계선.
- **오탐/탐지율**: 헛경보 비율 / 진짜 공격 잡은 비율.
- **에폭(epoch)**: 학습 데이터를 한 바퀴 다 본 횟수 (학습 반복 단위).
